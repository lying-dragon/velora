# VELORA

파워에 맞춰 3인칭 라이더가 달리는 개인용 실내 자전거 훈련 프로그램입니다. Three.js로 만든 순환 코스, 실시간 HUD, WebANT 기반 ANT+ 입력을 제공합니다. Zwift의 레이아웃을 참고했으며 그래픽·코스·UI는 자체 제작했습니다.

## 다운로드와 웹 체험

- [웹에서 바로 실행](https://jegarlyang.github.io/velora/)
- [Mac Apple Silicon 앱 다운로드](https://github.com/JeGarlyang/velora/releases/latest)
- [소스 코드](https://github.com/JeGarlyang/velora)

웹 버전은 설치 없이 체험할 수 있고, Strava 웹 자동 업로드는 Mac 앱에서 사용합니다. 실제 장치 지원과 사용법은 아래를 확인하세요.

## Mac 앱으로 실행

`release/VELORA-darwin-arm64/VELORA.app`을 응용 프로그램 폴더에 복사해 엽니다. Node 설치나 터미널이 필요 없습니다. 이 빌드는 Apple Silicon Mac용이며 개인 테스트용 서명되지 않은 앱입니다. 공개 배포에는 Developer ID 서명과 공증이 필요합니다.

첫 실행 안내에서 기능과 기기별 지원 범위를 확인하고 **다음 실행부터 이 안내 숨기기**를 선택하세요. 라이더 설정에서 다시 볼 수 있습니다. 자세한 배포 방법은 [배포 안내](docs/DISTRIBUTION.md)를 확인하세요.

## 소스로 실행

Node.js 22.12+가 필요합니다.

```sh
npm install
npm run dev
```

Chrome에서 **http://127.0.0.1:5173** 을 열고 **라이딩 시작**을 누르세요. 장비가 없어도 데모 파워 슬라이더로 달릴 수 있습니다.

- `Space`: 시작 / 일시정지 / 재개
- `←`, `→`: 데모 파워 10 W 조절
- `C`: 추적 / 와이드 / 사이드 카메라 전환
- 종료 → CSV 다운로드: 1초 간격 파워·케이던스·심박·거리·속도·입력 소스
- 화면을 다른 탭으로 전환하면 자동 일시정지합니다.

## ANT+ 연결 — WebANT 우선

1. Chrome/Edge에서 localhost를 열고 ANT+ USB 동글을 꽂습니다.
2. Garmin Express, Zwift 등 동글을 점유한 다른 앱을 종료합니다.
3. 상단 **데모 모드** → **ANT+ · 브라우저 직접 연결**을 선택합니다.
4. USB 권한 창에서 동글을 선택합니다. FE-C 로라가 기본 프로필입니다.
5. 페달을 밟아 파워가 들어오는지 확인하고 라이딩을 시작합니다.

동글 vendor ID `0x0fcf`(Dynastream)를 대상으로 WebUSB의 bulk IN/OUT 인터페이스를 사용합니다. WebUSB가 없는 환경에서는 Web Serial을 시도합니다. 장치 번호 0은 해당 프로필의 첫 수신 장치에 자동 연결합니다. 주변에 로라가 여러 대 있으면 장치 번호를 지정하세요. 자동 검색 목록에서 여러 센서를 골라 붙이는 UI는 아직 없습니다.

**WebANT 구현과의 관계:** upstream FE-C 디코더를 그대로 포함하며, 채널 설정·프로필·USB 전송 구조를 참고했습니다. 연결 수명 주기, 명령 응답 대기, 패킷 경계 복원, 체크섬 검사와 끊김 처리는 새 어댑터로 구현했습니다. 자세한 파일 대응과 커밋은 [ATTRIBUTION](docs/ATTRIBUTION.md)에 있습니다.

### USB 브리지 대안

브라우저의 USB 권한/드라이버 문제로 직접 연결이 안 되면 별도 터미널에서:

```sh
npm run bridge
```

그 후 **ANT+ · USB 브리지 연결**을 선택합니다. Node `ant-plus`가 Garmin USB-m (`0x1009`)와 USB2 (`0x1008`) 동글을 지원하며, 브리지는 `127.0.0.1:18765`에만 바인딩합니다. localhost Origin만 허용하며 장비를 쓰는 창을 하나로 제한합니다. 운영체제에 따라 USB 드라이버/접근 권한이 필요할 수 있습니다. 오류는 연결 창에 표시됩니다. `ant-plus`는 선택적 의존성이므로 설치에 실패해도 데모/WebANT는 사용할 수 있습니다.

### Bluetooth 대안

**Bluetooth**를 선택하면 Web Bluetooth로 FTMS Indoor Bike Data 또는 Cycling Power Measurement를 받습니다. Cycling Power 장치에서는 파워만 제공하며 케이던스·심박을 계산하지 않습니다. FTMS는 장치가 보내는 필드만 표시합니다. 없는 데이터는 `—`입니다.

## 구현된 기능

- 3인칭 자전거, 케이던스 기반 페달 애니메이션, 추적 카메라 3종
- 해안·설산·가을 공원·붉은 협곡·안개 숲·네온 도시 6개 순환 코스, 미니맵 위치, 랩 카운트, 경사와 획득 고도
- 파워, 체중, 경사, 공기 저항, 구름 저항 기반 가상 속도
- SIM 자동 경사 저항, ERG 자동 목표 파워, 부하 변화 완화
- 훈련 라이브러리: Z2 30분, LSD Butter 90분, Baguette 90분, Maple 80분, Dijon 57분, Pasta 70분, 회복 60분
- 현재/다음 단계 파워·권장 케이던스, 전체 구성·진행률·남은 시간, 강도 75–125% 조절, 단계 건너뛰기
- 체중·FTP 로컬 저장, FTP 대비 파워 존, 파워 타임라인
- 가상 페이서 3명 (네트워크 멀티플레이 아님)
- 데모와 실제 센서 입력 분리, 3초 이상 파워 데이터 미수신 시 0 W
- 세션 요약 및 CSV 내보내기 (측정되지 않은 필드는 빈 값)
- 데스크톱/모바일 반응형 UI

## 자동 저항과 훈련 사용법

1. 체중과 FTP를 설정합니다. 실제 로라를 연결한 뒤 유효한 파워 수신을 확인합니다.
2. 자유 라이딩을 시작하면 코스 경사에 따라 SIM 저항을 보냅니다.
3. 상단 **훈련 라이브러리**에서 유형을 고르고 세션 카드 → 단계표 → **이 훈련 선택**을 누릅니다.
4. 라이딩 시작 후 ERG가 목표 파워를 따릅니다. 워밍업·쿨다운은 선형 램프입니다.
5. 3D 화면과 분리된 훈련 패널에서 현재/다음 목표, 단계 남은 시간, 전체 진행률을 봅니다. 모바일에서도 표시됩니다.
6. `− / +`는 프로그램 강도를 5%씩 조절합니다. **자동 저항 OFF**는 부하를 해제하고 안내만 남깁니다.
7. 일시정지, 종료, 훈련 완료, 화면 숨김, 신호 끊김, 페달 정지 때 부하 해제 명령을 보냅니다. 파워가 없거나 케이던스가 0이면 훈련 시계도 멈춥니다.

ERG 상승은 약 25 W/s, 하강은 50 W/s, SIM 경사 변화는 2%p/s로 완화합니다. 부하 해제는 완화 없이 우선 전송합니다. ANT+는 전송 완료 이벤트로 **무선 수신 확인**을 표시합니다. 장치가 명령을 실제로 적용했는지나 실제 기계 저항을 측정한 확인은 아닙니다. FTMS는 Control Point 응답으로 거절/승인을 구분합니다. USB 브리지는 5초 이상 제어 갱신이 없거나 4초 이상 파워가 없으면 자체적으로 해제를 시도합니다. 브라우저/USB 자체가 종료되거나 물리적으로 끊어지면 해제를 보장할 수 없습니다.

## 현재 범위와 검증 한계

실행 가능한 초기 버전입니다. **실제 ANT+ 동글/스마트로라 하드웨어 테스트는 아직 수행하지 못했습니다.** 모의 WebUSB/FTMS 장치로 실제 전송 바이트, SIM↔ERG 전환, 파워 수신, 제어 실패, 신호 타임아웃과 부하 해제를 검증했습니다. 보유 장비의 USB 드라이버와 FE-C 방송 동작 확인이 필요합니다.

FE-C(직접 USB 및 브리지)와 Bluetooth FTMS 로라에 **SIM/ERG 제어 명령을 전송**합니다. 자유 주행은 코스 경사, 훈련은 FTP 기반 목표 파워를 따릅니다. 훈련 중에도 가상 이동 속도는 실측 파워와 실제 코스 경사로 계산하므로 오르막에서는 느려집니다. 케이던스는 권장 범위이며 로라가 강제하지 않습니다. 파워미터 전용 장치는 저항 제어를 지원하지 않으며 실패/미지원 상태를 표시합니다. 교정/스핀다운, ANT+ 전용 심박계 직접 페어링, 운동 FIT 파일, 계정·클라우드 저장·멀티플레이는 포함하지 않습니다. 진행 중 기록은 메모리에 보관됩니다. 종료한 기록은 로컬 서비스가 실행 중이면 컴퓨터에 저장하며, 실패하면 종료 화면에서 다운로드하세요.

그래픽과 코드는 로컬에서 동작합니다. Google Fonts를 사용하며 오프라인에서는 시스템 폰트로 대체됩니다. 센서 연결에는 Chrome/Edge와 localhost 또는 HTTPS가 필요합니다.

## 직접 만드는 훈련과 Ramp Test

- **훈련 라이브러리 → + 나만의 훈련 만들기**: 이름, 단계별 FTP %와 시간(초)을 입력합니다. `+ 단계 추가`로 이어 붙이고 손잡이 드래그 또는 ↑ ↓ 버튼으로 순서를 바꿉니다. 기존 카드를 선택해 **이 훈련 수정**으로 편집합니다. 사용자 훈련은 이 브라우저의 localStorage에 저장됩니다.
- **테스트 → Ramp Test · FTP 측정**: Flux 원본처럼 FTP 46%에서 5분 준비한 뒤 52%부터 매분 6%p씩 올립니다. 컨트롤러 한계 1,000 W를 넘는 단계는 제외합니다. 케이던스를 일정하게 유지하고 목표 파워를 유지할 수 없으면 **종료**하세요. 램프 구간에서 페달을 2초간 멈추면 결과 화면으로 전환합니다.
- 결과는 워밍업을 제외한 **최고 연속 60초 실측 평균 × 75%**인 FTP 추정치입니다. 목표 파워나 마지막 단계 숫자로 계산하지 않습니다. 한계까지 수행했다는 체크 후 **이 결과를 내 FTP에 적용**하면 프로필에 저장됩니다. 데모, 부족한 기록, 신호 끊김, 일시정지, 장치/설정 변경, 제어 실패, 테스트 상한 도달 결과는 적용할 수 없습니다. 개인차가 있으며 FTP의 직접 측정값은 아닙니다.
- 훈련 HUD는 3D 캔버스와 겹치지 않는 하단 전용 영역에 배치됩니다. 가로로 짧은 화면은 오른쪽 전용 영역을 사용합니다.
- 케이던스 25–65 rpm, 추정 크랭크 토크 40 Nm 초과, 파워 FTP 85% 이상이 1.2초 지속되면 댄싱 애니메이션으로 전환합니다. 몸이 일어서고 자전거가 좌우로 흔들리며 팔·다리가 핸들과 페달을 따라갑니다. 실제 자세를 측정한 것이 아닌 시각적 추정입니다.

## 실시간 장비 상태

상단 바에서 파워·심박·케이던스·로라 상태를 항상 확인합니다. 초록은 수신 중, 노랑은 신호 대기/신호 없음, 회색은 미연결, 데모는 가상 데이터입니다. 클릭하면 장치 이름과 수신 경로를 확인합니다. 파워 데이터는 3초, 별도 심박은 5초 미수신 시 유효한 수신으로 표시하지 않습니다. 파워 0 W·케이던스 0 rpm도 정상 수신값입니다.

케이던스는 현재 로라/파워 장치가 제공하는 값입니다. 별도 케이던스 센서 직접 연결을 구현한 것은 아닙니다. 심박은 별도 Bluetooth 연결 또는 로라 중계를 구분합니다. 로라의 ‘제어 가능’은 연결된 제어 경로를 뜻하며 실제 저항을 측정한 결과가 아닙니다.

## 별도 심박계

**장치 연결 → Bluetooth 심박계 연결**에서 표준 Heart Rate Service(0x180D)를 지원하는 심박계를 별도로 선택합니다. ANT+ 로라와 Bluetooth 심박계를 함께 사용할 수 있습니다. 0x2A37의 8/16비트 심박수와 접촉 상태를 해석하며 5초 미수신이면 `—`로 표시합니다. 별도 심박계가 연결되어 있으면 그 값을 우선하고, 해제하면 로라 중계 심박수로 돌아갑니다. 파워 연결 변경과 독립적으로 유지됩니다.

Bluetooth 미지원 브라우저나 ANT+ 전용 심박계는 이 연결 경로를 사용할 수 없습니다. **실물 심박계 연결은 검증하지 않았으며**, 모의 GATT 알림·타임아웃·해제와 패킷 파싱을 테스트했습니다.


## 산 정상 깜박임 수정

기존에는 큰 산 원뿔과 그 위의 작은 눈 원뿔이 거의 같은 위치에 겹쳐 원거리 깊이 버퍼 충돌(z-fighting)이 발생할 수 있었습니다. `mountainGeometry`는 눈/암석을 서로 겹치지 않는 삼각형으로 구성합니다. 먼 산의 그림자 수신/생성을 끄고 카메라 near를 0.1→0.5 m로 조정해 깊이 정밀도도 개선했습니다. 다른 물체의 재질은 유지합니다.

## 재시작 후에도 기억하는 설정

`npm run dev`는 화면(5173)과 저장·Strava 서비스(18766)를 함께 시작합니다. 화면 주소가 바뀌어 저장소가 달라지지 않도록 5173 포트를 고정합니다. 기존 화면 서버가 실행 중이면 `npm run integrations`로 서비스만 켤 수 있습니다.

- 체중·FTP·내 훈련은 브라우저 localStorage에 즉시 저장하고 `~/.velora/settings.json`에도 자동 백업합니다.
- 선택한 코스·훈련·카메라·자동 저항 설정·ANT 프로필/장치 번호도 복원합니다. 장치의 USB/Bluetooth 권한은 브라우저 정책에 따라 다시 선택해야 할 수 있습니다.
- 키별 저장 시각을 비교해 최신 값을 복원합니다. 기존 저장 자료는 자동 이관됩니다. 창을 닫거나 컴퓨터를 재시작한 뒤 `npm run dev`로 다시 열면 유지됩니다.
- `~/.velora`는 저장 폴더이며 삭제하면 컴퓨터 백업도 사라집니다. 브라우저 데이터까지 삭제하면 복구할 수 없습니다. 다른 컴퓨터로 옮길 때 폴더 전체를 안전하게 보관하세요. 계정 비밀이 포함되어 있으므로 공개 저장소에 넣지 마세요.
- 종료한 기록, TCX, 공유 PNG, 업로드 상태는 `~/.velora/rides.json`에 저장됩니다. 설정의 최근 종료 기록에서 다시 다운로드할 수 있습니다.

## Strava 웹 업로드 — API 사용 안 함

1. Mac 앱에서 **라이더 설정 → 저장과 Strava 웹 업로드 → Strava 로그인 창 열기**를 누릅니다.
2. 앱 안의 Strava 창에 한 번 로그인합니다. 기존 Chrome/Codex 로그인 쿠키를 복사하지 않습니다. 로그인 세션은 앱 전용 브라우저에 유지됩니다.
3. **종료 시 Strava 웹 업로드 자동 시작**을 켜면 10초 이상 실제 센서 기록 종료 시 TCX 파일 선택 → 제목·설명 → 실내 라이딩·나만 보기 → 저장 → 사진 첨부 → 저장을 실행합니다. 데모는 자동 전송하지 않습니다.
4. 최근 기록의 **웹 업로드**로 수동 시작할 수도 있습니다. 업로드가 확인되면 Strava 활동 링크를 표시합니다. 공개 범위는 항상 **나만 보기**로 시작하며 Strava에서 직접 변경할 수 있습니다.

파워·케이던스·측정된 심박·가상 거리를 TCX에 담습니다. 실제 GPS 좌표를 만들지 않습니다. 제목·설명·1200×800 이미지 카드를 자동 생성합니다. API 키, OAuth 토큰, 유료 개발자 등록은 사용하지 않습니다. 웹 버전에서는 보안상 다른 사이트를 자동 제어할 수 없어 TCX·PNG 다운로드와 문구 복사를 제공합니다.

로그인 만료, 사람 확인, Strava 화면 변경, 네트워크 오류가 있으면 자동화를 멈추고 창에서 확인하도록 안내합니다. 활동 ID가 확인됐으면 해당 활동 편집을 이어갑니다. 전송 결과가 불확실하고 ID가 없으면 중복 생성을 막기 위해 재전송하지 않습니다. 이때 Strava 업로드 화면을 확인하세요. 사진이 저장된 화면까지 확인해야 완료로 표시합니다.
