# VELORA 설계

## 데이터 흐름

```text
WebANT USB / Serial ────┐
ANT+ Node 브리지 ────────┼─ Reading(W, rpm?, bpm?) ── 3초 신호 검사
Bluetooth FTMS / CPS ───┤                                │
데모 파워 슬라이더 ────────┘                                ▼
                                              물리 엔진 (SI 단위)
                                         파워 + 질량 + 경사 → m/s
                                                       │
                                         누적 거리 / 시간 / 에너지
                                            ┌──────────┼──────────┐
                                            ▼          ▼          ▼
                                        3D 라이더     HUD/지도    CSV 샘플
```

## 주행 모델

단위는 내부적으로 m, s, kg, W입니다. 출력만 km/h와 km로 변환합니다.

- 구동력: `min(180, 0.97 × watts / max(speed, 0.5))` (출발 시 무한 가속 방지)
- 중력: `mass × g × sin(atan(grade))`
- 구름 저항: `mass × g × 0.004 × cos(atan(grade))`
- 공기 저항: `0.5 × 1.225 × 0.32 × speed²`
- `acceleration = (구동력 - 저항력) / (mass + 1.5)`; 1.5 kg는 회전 관성 등가 질량
- 질량 = 라이더 체중 + 자전거 8 kg
- 20 ms 이하 하위 스텝과 midpoint 적분으로 프레임 간 오차를 줄이고 속도를 음수로 만들지 않습니다.
- 파워가 0이면 평지에서 관성으로 감속하고 내리막에서는 중력에 따라 굴러갑니다.

코스의 실제 3D 곡선 길이를 사용해 거리를 진행시키며, 미니맵과 화면 위치를 같은 진행률로 계산합니다. 고도는 상승분만 적산합니다. 횡가속도 1.8 m/s²와 전방 45 m의 곡률로 코너 진입 속도를 계산하고 최대 3 m/s²로 감속합니다. 드래프팅과 실제 바람은 포함하지 않습니다. 경사 보정·속도는 의료적 측정 또는 실외 속도 예측 용도가 아닌 게임 시뮬레이션입니다.

## ANT+ 구현

WebANT의 채널 프로필을 기준으로 FE-C(type 17, period 8192, RF 57)를 설정합니다. Bicycle Power(type 11, period 8182)는 추가 구현입니다.

1. Dynastream USB 동글 선택 → bulk IN/OUT endpoint 검색 → 인터페이스 claim.
2. ANT reset(0x4a) 후 startup(0x6f)을 기다립니다.
3. network key → assign → channel ID → frequency → period → search timeout → open을 명령별 응답 확인 후 진행합니다.
4. 0xA4 sync/길이/XOR 체크섬을 검증하며 USB 패킷 간 분할된 ANT 프레임을 복원합니다.
5. FE-C page 25(파워·케이던스), page 16(심박)을 해석합니다. Power page 16도 지원합니다.
6. 파워 invalid sentinel(4095/65535)와 케이던스/심박 invalid 값(255)을 필터링합니다.
7. 마지막 유효 파워 패킷 이후 3초가 지나면 0 W / rpm·bpm 미수신으로 표시합니다.
8. 입력 변경 시 이전 연결을 닫고 generation으로 늦게 도착한 이벤트를 무시합니다.

FE-C 제어는 acknowledged data(0x4F)에 page 55(라이더/자전거), 50(바람/공기저항), 51(경사) 또는 49(목표 파워)를 보냅니다. 부하 해제는 page 48의 저항 0입니다. 전송 완료/실패 이벤트(5/6)를 기다리며 단순 USB write 성공을 적용 성공으로 표시하지 않습니다. page 71의 명령 적용 상태는 현재 구현하지 않았으므로 UI는 **전송 확인**이라고 표시합니다.

FTMS는 Feature의 Power/Simulation 지원 비트와 Supported Power Range를 읽고, Control Point의 indication을 구독합니다. Request Control(0) → 목표 Power(5)/Simulation(17) → Start(7) 순서이며 Stop(8,1)으로 정지합니다. 응답 opcode 0x80의 결과 코드를 검증합니다. FTMS 시뮬레이션에는 체중 필드가 없어 로라의 내부 사용자 설정을 사용합니다.

`trainer-control.ts`는 명령을 한 번에 하나씩 전송하며, 대기열에는 가장 최신 명령만 둡니다. 정지는 대기 중 부하 명령을 덮어씁니다. 명령 오류 이후 해제를 시도하되 오류 문구를 유지합니다. 동일 해제 명령의 중복 적재로 연결 변경을 무한 대기하지 않도록 검사합니다. `bridge/control.mjs`는 Node FE-C 드라이버에 같은 제어를 적용하며 서버 watchdog이 브라우저의 갱신 중단을 감시합니다.

## UI와 기록

상단 주행 요약, 좌측 파워·훈련, 우측 지도·페이서, 하단 파워 그래프를 배치했습니다. 훈련 모드에서는 라이더를 가리지 않도록 3D 캔버스와 겹치지 않는 하단 전용 영역에 현재/다음 단계와 전체 진행률을 모읍니다. 모바일에서도 훈련 패널을 유지하며 상단 라이브러리 버튼으로 선택할 수 있습니다. 기록은 활성 주행 중에만 1초 간격으로 수집합니다. 평균 파워는 0 W 구간을 포함한 시간 적분으로 계산합니다. 데모 기록도 입력 소스를 명시합니다.

프로필 설정과 검증한 사용자 훈련을 localStorage에 저장합니다. 라이드 기록은 메모리에 두고 사용자가 CSV로 저장합니다. 훈련/코스 변경 화면에 기록 초기화를 명시합니다. 탭이 숨겨지면 시뮬레이션을 일시정지하며 재개는 수동입니다.

## 검증

- 단위 테스트: 파워/경사/질량, 코스팅, 훈련 단계 경계, ANT 프레이밍/체크섬/분할 수신, FE-C invalid 값, Bluetooth 가변 필드 오프셋.
- Chrome E2E: 시작/정지/재개, 파워 변경과 가속, 프로필 저장, 코스/훈련 변경, CSV, 브리지 부재, 모바일 overflow.
- 가상 USB: ANT startup 및 명령 ACK를 모의하고 FE-C 방송이 실제 어댑터부터 주행 UI까지 도달하는지 확인. 이후 전송 중단 후 0 W 확인.
- 실물 동글 연결, 로라별 전파 수신, Windows USB 드라이버와 실제 기계 저항의 적용 여부는 검증하지 않았습니다.


## 훈련 엔진과 Flux 출처

`src/workouts/flux.json`과 `public/workouts/*.zwo`에는 Flux의 Butter, Baguette, Maple, Dijon, Pasta, Blackcurrant 원본 시간/FTP 비율을 보존합니다. 워밍업/쿨다운 PowerLow→PowerHigh를 선형 보간하고 IntervalsT를 반복/회복 단계로 펼칩니다. Z2 30분은 VELORA가 Butter의 강도를 참고해 단축한 별도 변형입니다. 원본에 없는 케이던스 범위는 VELORA 권장으로 명시합니다. IF/TSS는 계획 파워의 4제곱 평균에 기반한 추정치이며 실제 운동의 정확한 NP/TSS가 아닙니다.

훈련 시간은 주행 시간과 분리합니다. 실측 파워가 5 W 이하, 케이던스가 0, 또는 센서가 stale이면 프로그램 진행을 멈춥니다. 훈련 중에는 경사 명령 대신 ERG만 보냅니다. 가상 속도에는 계속 실제 지형을 반영합니다. 완료 시 자동 정지·해제하며 갑자기 SIM 모드로 바꾸지 않습니다.

## 속도 이상치 재현과 개선

기존 알파인 코스에서 165 W로 시뮬레이션하면 급격한 내리막→오르막 전환 때문에 경사 약 4.9%에서 75.3 km/h의 순간값을 재현했습니다. 정상상태의 힘 계산 오류보다는 짧은 급경사 코스와 코너 감속 부재가 원인이었습니다. 산악 코스를 2.52 km로 확장하고 고도 곡선을 완만하게 바꾸었으며 코너 감속을 추가했습니다. 같은 출력의 회귀 시뮬레이션에서 경사 4.5% 이상 구간의 최고 속도는 약 17.1 km/h입니다.

83 kg 총 질량, CdA 0.32 m², Crr 0.004, 공기밀도 1.225 kg/m³, 구동 효율 97% 조건에서 +5%·200 W의 정상상태 속도는 14.79 km/h입니다. 같은 경사에서 50 km/h를 지속하려면 약 1,170 W가 필요합니다. 일시적인 관성은 유지하며 오르막 진입 즉시 평형 속도로 강제 고정하지 않습니다. 이 수치는 설정한 모델의 예시이며 사용자/장비 실측 검증은 아닙니다.

최종 검증: 단위 테스트 20개와 Chrome E2E 테스트 14개, TypeScript/Vite 빌드 통과. E2E에는 FE-C 실제 전송 바이트, FTMS 요청/응답, 미지원 제어, 정지·신호 끊김 해제, 모바일 화면 검증이 포함됩니다.


## 사용자 훈련 / 램프 평가 / 시각적 자세

- `workout-editor.ts`: 저장 전과 읽기 시 동일 검증. 단계 1–100개, FTP 10–250%, 각 1–7,200초, 총 6시간 제한. 이름은 HTML escape, 외부 데이터의 source/label 등은 폐기 후 정규화. 저장소 오류는 편집기에 표시하고 성공으로 보고하지 않습니다. 드래그와 키보드/터치용 순서 버튼을 함께 제공합니다.
- `ramp-test.ts`: 워밍업 이후 실제 파워를 프레임별 시간 가중 적분하고 60초 이동 창의 최고 평균을 유지합니다. 마지막 미완료 단계도 포함합니다. 테스트 중단 사유는 유지되어 재개로 유효성을 되찾지 않습니다. 파워와 프로그램 시계는 분리하며, 제어 실패·신호 단절·데모·프레임 기록 중단은 적용을 차단합니다. 수동 종료 또는 램프 페달 정지 2초 후 부하 해제를 요청하고 결과를 표시합니다.
- `heart-rate.ts`: 독립 GATT 연결 및 알림 수명 관리. 파워의 신호 타이머와 분리하고 수신 후 5초가 지난 값은 표시하지 않습니다. 실물 검증 전입니다.
- `rider-motion.ts`: 파워/각속도에서 크랭크 토크를 추정하고 진입 지연, 이탈 히스테리시스, 지수 보간으로 앉기/서기를 전환합니다. 실제 자세 분류기는 아닙니다. Three.js 자전거·몸통 그룹과 팔/다리 관절 위치를 분리합니다.
- `ResizeObserver`로 훈련 모드 전환 시 캔버스 영역과 카메라 종횡비를 갱신합니다.

FTP 적용 E2E는 60초 측정 창을 모의 데이터로 주입하고 실제 종료·확인·프로필 저장 핸들러를 검증합니다. 측정 창의 시간 가중 계산과 무효화는 별도 단위 테스트에서 검증합니다.


## 로컬 저장 및 웹 업로드

`persistence.ts`는 localStorage와 `~/.velora/settings.json`을 키별 수정 시각으로 동기화합니다. 종료 기록과 생성한 TCX·PNG는 `rides.json`, 자동 전송 설정은 `web-upload.json`에 저장합니다. `services/server.mjs`는 localhost Origin만 받으며 Strava로 네트워크 요청을 보내지 않습니다.

`desktop/main.cjs`는 Electron 창과 로컬 정적 서버·저장 서비스를 실행합니다. 앱 렌더러는 sandbox/contextIsolation을 사용하고 preload의 제한된 IPC만 노출합니다. Strava 창은 별도 영구 세션, Node 비활성화, preload 없음으로 분리합니다. `desktop/strava-ui.cjs`는 관찰한 웹 폼을 선택자로 조작하고 파일 input에 TCX·PNG를 지정합니다. API, 계정 비밀번호, 쿠키 추출은 사용하지 않습니다.

업로드 상태는 local → uploading → complete 또는 needs_login/needs_review입니다. TCX 전송 전에 uploading을 디스크에 기록합니다. 생성된 activityId가 있으면 사진 단계에서 재개하고, 없는 불확실한 전송은 반복하지 않습니다. 새 활동을 나만 보기와 Indoor Cycling으로 저장하고, 최종 활동 페이지에서 제목·공개 범위·미디어 썸네일을 확인합니다.

`onboarding.ts` 안내 완료 여부도 설정과 함께 저장합니다. PWA 서비스 워커는 방문한 앱 자원만 캐시합니다. 계정 동기화나 모바일의 PC 로컬 서비스 접근은 제공하지 않습니다. 여섯 코스는 서로 다른 곡선·고도·팔레트·환경 오브젝트를 사용합니다.
